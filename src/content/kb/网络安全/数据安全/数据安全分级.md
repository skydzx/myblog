## 1. 数据安全分级概念

数据安全分级 = 根据**数据敏感性、重要性、影响程度**三个维度，将数据划分为不同安全等级，实施差异化保护。

核心三要素：

```text
敏感性  数据对个人隐私、商业机密、国家安全的敏感程度
重要性  数据在业务流程、决策支持、运营管理中的价值地位
影响程度  数据泄露/篡改/破坏后造成的损失范围（经济、声誉、法律、社会）
```

体现"**分类管理、重点保护**"理念，实现安全资源优化配置。

## 2. 法律政策依据

| 法律/标准 | 时间 | 要点 |
|-----------|------|------|
| 《网络安全法》 | 2016.11 | 首次在法律层面提出数据分类保护要求 |
| 《数据安全法》 | 2021.6 | 建立数据**分类分级**保护制度，明确法律依据 |
| 《个人信息保护法》 | 2021.8 | 细化个人信息分类管理要求 |
| GB/T 37973-2019 | - | 数据安全能力成熟度模型（5 级） |
| GB/T 35273-2020 | - | 个人信息安全规范（敏感/一般两大类） |
| GB/T 37988-2019 | - | 数据安全能力成熟度模型 |
| JR/T 0197-2020 | - | 金融数据安全分级指南（5 级） |
| GB/T 38667-2020 | - | 数据脱敏技术规范 |

## 3. 传统数据分级方法

| 方法 | 原理 | 局限 |
|------|------|------|
| **关键词匹配** | 维护敏感词词典做字符串匹配 | 词汇覆盖不全、无语义理解、"身份证号码 vs 复印件"无法区分 |
| **正则表达式** | 模式识别身份证/手机号/银行卡 | 对非结构化/语义复杂内容识别弱，维护成本高 |
| **统计特征** | 分布/唯一性/熵值评估 | 缺语义理解，随机测试数据可能误判为高敏感 |

传统方法共同局限：缺语义理解、规则更新滞后、无上下文感知、难应对海量实时数据。

## 4. 基于规则的分级技术

核心是构建**规则库 + 多因子加权评分**：

```text
规则库三层：
- 敏感字段词典：敏感词 + 敏感度权重
- 模式匹配规则：身份证/手机号/邮箱等正则 + 安全等级
- 业务规则：结合使用场景定义安全要求

评估算法（多因子加权评分）：
- 字段名称评分：字段名语义特征
- 数据内容评分：模式匹配 + 关键词
- 业务上下文评分：使用场景 + 访问权限
```

优点：可解释性强、处理快、维护成本低；局限：规则覆盖不全、语义弱、适应性差。

## 5. 基于机器学习的分级技术

通过训练分类模型自动学习数据安全特征，处理复杂非结构化数据，自适应与泛化能力强：

```text
流程：标注样本 → 特征工程 → 训练分类模型 → 预测分级
能结合语义与上下文，弥补规则方法的不足
```

---

> **一句话总结**：数据分级 = 依据敏感/重要/影响三要素分类，法律支撑（网安法/数安法/个保法）+ 标准落地（GB/T），技术上从"关键词/正则"走向"规则评分 + 机器学习"。
