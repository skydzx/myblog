## 1. auditd 审计

```bash
systemctl enable --now auditd
auditctl -l        # 查看现有规则
```

加固规则 `/etc/audit/rules.d/hardening.rules`：

```bash
cat > /etc/audit/rules.d/hardening.rules << 'EOF'
# 身份文件变更
-w /etc/passwd -p wa -k identity
-w /etc/shadow -p wa -k identity
-w /etc/group -p wa -k identity
-w /etc/gshadow -p wa -k identity
-w /etc/sudoers -p wa -k sudoers
-w /etc/sudoers.d/ -p wa -k sudoers

# 登录文件
-w /var/log/lastlog -p wa -k logins
-w /var/run/faillock/ -p wa -k logins

# 权限变更
-a always,exit -F arch=b64 -S chmod,fchmod,fchmodat -k perms
-a always,exit -F arch=b64 -S chown,fchown,lchown -k perms

# 关键命令执行
-w /usr/bin/su -p x -k priv_esc
-w /usr/bin/sudo -p x -k priv_esc
-w /usr/bin/passwd -p x -k identity
-w /usr/bin/useradd -p x -k identity
-w /usr/bin/usermod -p x -k identity
-w /usr/bin/userdel -p x -k identity

# 审计日志本身不可篡改
-e 1
EOF

augenrules --load
auditctl -l    # 验证
```

查询审计日志：

```bash
ausearch -k identity --start today
ausearch -k priv_esc --start today
aureport --auth --summary
```

## 2. rsyslog / journald

```bash
systemctl status rsyslog
# 日志文件权限期望 640/600, root:root
ls -la /var/log/secure /var/log/messages /var/log/auth.log /var/log/syslog 2>/dev/null

# 远程日志转发（防本地篡改）
# /etc/rsyslog.conf 添加:
# *.* @@log-server.internal:514    # TCP（推荐，可靠）
# 或 *.* @log-server.internal:514   # UDP

# 日志轮转测试
logrotate -d /etc/logrotate.conf    # dry-run

# journald 持久化
mkdir -p /var/log/journal
systemd-tmpfiles --create --prefix /var/log/journal
systemctl restart systemd-journald
journalctl --disk-usage
```

> 日志是溯源的核心。单机日志可被攻击者篡改，**生产环境务必配置远程日志转发**。

## 3. 命令历史记录加固

```bash
cat >> /etc/profile.d/history.sh << 'EOF'
export HISTTIMEFORMAT="%F %T "
export HISTSIZE=10000
export HISTFILESIZE=10000
export HISTCONTROL=""
shopt -s histappend
EOF
chmod 644 /etc/profile.d/history.sh
```

> `HISTCONTROL=""` 关闭忽略重复/空格开头命令，保证审计完整性；有隐私顾虑可改用 `HISTCONTROL=ignoredups`。

## 4. SELinux（RHEL/CentOS）

```bash
getenforce
sestatus
# 期望: Enforcing / Current mode: enforcing

# 若为 Disabled/Permissive，改为 Enforcing（需重启生效）
sed -i 's/^SELINUX=.*/SELINUX=enforcing/' /etc/selinux/config

# 查看用户映射 / 端口标签 / 布尔值
semanage login -l
semanage port -l
getsebool -a

# 被拒绝的事件
ausearch -m avc -ts recent
cat /var/log/audit/audit.log | grep "denied"

# 排查问题（不关闭 SELinux）
ausearch -m avc -ts recent | audit2allow -M mypolicy
semodule -i mypolicy.pp
```

> 遇到 SELinux 阻止应用，**不要直接 `setenforce 0`**——用 `ausearch + audit2allow` 生成放行策略才是正解。

## 5. AppArmor（Ubuntu/Debian）

```bash
aa-status
systemctl status apparmor

# 查看已加载 profiles
aa-status | head -20
ls /etc/apparmor.d/

# 设置 enforce 模式
aa-enforce /etc/apparmor.d/<profile_name>

# 被拦截事件
journalctl | grep apparmor | tail -50
dmesg | grep apparmor | tail -50
```

## 6. 内核安全模块确认

```bash
# 内核编译选项
grep -E "CONFIG_SECURITY|CONFIG_SELINUX|CONFIG_APPARMOR" /boot/config-$(uname -r)

# 启动参数
cat /proc/cmdline | grep -o "security=[a-z]*"
cat /proc/cmdline | grep -o "selinux=[0-1]"
```
