## 1. OpenSCAP（CIS / 等保扫描）

```bash
yum install -y openscap-scanner scap-security-guide   # RHEL
apt install -y openscap-scanner ssg-base              # Ubuntu

# 查看可用 Profile
oscap info /usr/share/xml/scap/ssg/content/ssg-rhel8-ds.xml | grep "Profile"

# 执行 CIS Level 1 扫描（生成报告）
oscap xccdf eval \
  --profile xccdf_org.ssgproject.content_profile_cis \
  --results /tmp/scan-results.xml \
  --report /tmp/scan-report.html \
  /usr/share/xml/scap/ssg/content/ssg-rhel8-ds.xml

# 自动修复（⚠️ 先备份/测试环境验证）
oscap xccdf eval \
  --profile xccdf_org.ssgproject.content_profile_cis \
  --remediate \
  --results /tmp/fix-results.xml \
  /usr/share/xml/scap/ssg/content/ssg-rhel8-ds.xml
```

> OpenSCAP 的 `--remediate` 会直接改系统，务必先在测试机验证，生产环境慎用。

## 2. Lynis（系统审计）

```bash
yum install -y lynis           # RHEL (EPEL)
apt install -y lynis           # Ubuntu

# 执行系统审计
lynis audit system

# 仅检查特定测试项
lynis audit system --tests SSH-7408,DBS-1804

# 报告
cat /var/log/lynis.log
cat /var/log/lynis-report.dat
```

## 3. Ansible 批量加固

```bash
pip install ansible
# 或 yum install -y ansible

# 社区加固集合
ansible-galaxy collection install devsec.hardening

# 先 dry-run 预览改动
ansible-playbook -i inventory.ini --check --diff devsec.hardening.os_hardening
# 正式执行
ansible-playbook -i inventory.ini devsec.hardening.os_hardening
```

自定义加固任务：

```yaml
---
- hosts: all
  become: yes
  tasks:
    - name: 设置密码策略
      lineinfile:
        path: /etc/login.defs
        regexp: '^{{ item.key }}'
        line: '{{ item.key }} {{ item.value }}'
      loop:
        - { key: 'PASS_MAX_DAYS', value: '90' }
        - { key: 'PASS_MIN_DAYS', value: '7' }

    - name: 禁止 root SSH 登录
      lineinfile:
        path: /etc/ssh/sshd_config
        regexp: '^PermitRootLogin'
        line: 'PermitRootLogin no'
      notify: restart sshd

  handlers:
    - name: restart sshd
      systemd:
        name: sshd
        state: restarted
```

## 4. 自定义合规检查脚本框架

一个可复用的 `check` 函数，按"检查项 → 期望值"批量评估：

```bash
#!/bin/bash
# compliance_check.sh - 安全基线一键检查
# 用法: bash compliance_check.sh > report_$(date +%F).txt

RED='\033[0;31m'; GREEN='\033[0;32m'; NC='\033[0m'
PASS=0; FAIL=0

check() {
    local desc="$1"; local cmd="$2"; local expect="$3"
    result=$(eval "$cmd" 2>/dev/null)
    if echo "$result" | grep -qE "$expect"; then
        echo -e "${GREEN}[PASS]${NC} $desc"; ((PASS++))
    else
        echo -e "${RED}[FAIL]${NC} $desc"; ((FAIL++))
    fi
}

echo "== Linux 安全基线检查: $(hostname) | $(date) =="

echo -e "\n--- [1] 账号安全 ---"
check "无空口令账号" "awk -F: '(\$2==\"\"){print}' /etc/shadow | wc -l" "^0$"
check "无UID=0异常账号" "awk -F: '(\$3==0 && \$1!=\"root\"){print}' /etc/passwd | wc -l" "^0$"

echo -e "\n--- [2] SSH安全 ---"
check "Root远程登录已禁止" "grep '^PermitRootLogin' /etc/ssh/sshd_config" "^PermitRootLogin no"

echo -e "\n--- [3] 口令策略 ---"
check "密码最长有效期≤90天" "grep '^PASS_MAX_DAYS' /etc/login.defs | awk '{print \$2}'" "^(90|[1-8][0-9])$"

echo -e "\n--- [4] 文件系统 ---"
check "shadow文件权限≤400" "stat -c '%a' /etc/shadow" "^(000|400|0)$"
check "umask已设置" "grep 'umask' /etc/login.defs | tail -1" "umask 0[2-7][2-7]"

echo -e "\n--- [5] 内核参数 ---"
check "IP转发已关闭" "cat /proc/sys/net/ipv4/ip_forward" "^0$"
check "ASLR已启用" "cat /proc/sys/kernel/randomize_va_space" "^2$"

echo -e "\n--- [6] 审计日志 ---"
check "auditd运行中" "systemctl is-active auditd" "^active$"
check "rsyslog运行中" "systemctl is-active rsyslog" "^active$"

echo -e "\n--- [7] SELinux/AppArmor ---"
check "SELinux为Enforcing" "getenforce 2>/dev/null || echo 'N/A'" "^(Enforcing|N/A)$"

echo -e "\n== 结果: PASS=$PASS  FAIL=$FAIL =="
```

## 5. 综合检查脚本（含中间件 + 数据库）

把前面的检查项整合成一个大脚本，覆盖 Redis/MySQL/PG/Tomcat/Nginx 等，自动输出 `[PASS]/[FAIL]/[SKIP]`（未安装的服务显示 SKIP）。核心框架与上面相同，按需添加 `check "描述" "命令" "期望正则"` 即可。

## 6. 合规落地建议

1. **基线文档化**：把加固项写成 playbook / 检查脚本，纳入版本管理
2. **定期巡检**：cron 定时跑 OpenSCAP/Lynis，输出报告
3. **变更即验证**：每次改系统配置后重跑检查脚本，防止漂移
4. **从检查到整改闭环**：FAIL 项要有负责人 + 期限，别只生成报告不跟进
